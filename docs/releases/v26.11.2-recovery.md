# Kurtarma — Coreor Database v26.11.2

GitHub release `444914553`, yanlışlıkla `untagged-910018b0b9ff05e96171` etiketinde yayımlandı.
İmzalı dört platformun 11 paketi zaten mevcuttur. Tekrar build veya sürüm artırma gerekmez.

## 1. Eksik Git etiketini oluştur

GitHub Actions'ın `GITHUB_TOKEN` token'ı bu repoda `POST /git/refs` için
`403 Resource not accessible by integration` alıyor. Tag oluşturmayı Actions
workflow'undan kaldırdık. Depo sahibinin bilgisayarında:

```powershell
git fetch origin
git tag v26.11.2 33749df96458c7dd4659ddd0fe326487a9f7fdc3
git push origin v26.11.2
```

Eğer etiket zaten varsa tekrar oluşturma: `git rev-list -n 1 v26.11.2`
ile commit kimliğini kontrol et. **Yayımlanmış tag'i başka commit'e taşıma.**

## 2. Release kurtarma

GitHub → Actions → **Recover v26.11.2 updater release** → Run workflow → main.

İş akışı:
- Önce etiketi ve doğru commit'i doğrular; yoksa hiçbir release dosyasını değiştirmeden durur.
- Yayınlanmış release etiketini `v26.11.2` olarak günceller.
- `latest.json` içindeki API asset-ID adreslerini public download URL'lerine dönüştürür.
- Orijinal manifesti geçici adla tutar; yeni manifestin doğrulanmasından sonra yedeği siler.

GitHub'ın varsayılan token'ı release değiştirme işlemleri için de 403 döndürürse,
depo ayarlarında `COREOR_RELEASE_ADMIN_TOKEN` secret'ına yalnızca bu repo için
**Contents: Read and write** yetkili fine-grained token tanımla. Token'ı koda,
loglara veya sohbet mesajlarına kopyalama.

## 3. Doğrulama

İş akışı success olmalı, ardından aşağıdaki iki URL'yi kontrol et:

- https://github.com/battincik/coreor-database/releases/tag/v26.11.2
- https://github.com/battincik/coreor-database/releases/download/v26.11.2/latest.json

Uygulama `v26.11.1` → Ayarlar → Güncellemeler → Şimdi kontrol et.
Güncelleme API'sinin CDN/cache katmanı varsa önbellek sona erdikten sonra
yeniden kontrol et. Uygulamanın yalnızca sürüm adını algılaması, imzalı
manifestin geçerli olduğunu ve kurulumun çalıştığını tek başına doğrulamaz.
