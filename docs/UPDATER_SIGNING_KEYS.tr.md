# GitHub Actions updater signing key

The `Signed release candidate` workflow uses the **same original key pair** for all versions and operating systems.

- **Repository variable** `COREOR_UPDATER_PUBLIC_KEY`: paste the entire content of the `*.key.pub` file generated by `tauri signer generate`. Tauri's generated `.pub` file is usually one long base64 line that decodes into **both** minisign lines: an `untrusted comment: minisign public key ...` header and the `RW...` public key body. Do **not** paste only the `RW...` line, and do not paste the local file path.
- **Repository secret** `TAURI_SIGNING_PRIVATE_KEY`: original `.key` private key contents, never published or committed.
- **Repository secret** `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: password for that private key, if set.

The workflow's `scripts/prepare-signed-release.mjs` validates the public key and writes its normalized base64 form into the **release-only** `src-tauri/tauri.release.conf.json` config overlay. No private signing material is saved to the repository, and local dev configuration remains unchanged.

If the validation reports `Missing comment in public key` or `expected the FULL .pub file`, update the GitHub repository variable using the **original matching public key**. A public key is not interchangeable with another private key; generating a fresh pair breaks update verification for existing installs.

After merging the fix to `main`, start a new `Signed release candidate` run for the existing `v26.11.1` source. **Do not bump the version again**. Inspect the draft release and its updater manifest before publishing.
