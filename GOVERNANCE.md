# Governance

Coreor Database currently uses a maintainer-led governance model.

## Maintainers

Maintainers are responsible for:

- project direction and roadmap,
- reviewing and merging pull requests,
- release decisions,
- security response,
- dependency and platform support policy,
- enforcing the code of conduct.

## Contributions

Significant changes should normally be proposed through an issue or pull request so design, security, performance and cross-platform effects can be reviewed.

Small bug fixes and documentation corrections do not require a separate design proposal.

## Decision making

Technical decisions prioritize:

1. data safety,
2. local-first architecture,
3. cross-platform maintainability,
4. performance,
5. database-engine correctness,
6. accessibility and workflow quality.

When consensus is not reached, maintainers make the final project decision and should document the rationale for material architectural choices.

## Security

Security vulnerabilities follow the private process in [SECURITY.md](SECURITY.md), not ordinary issue discussion.

## Project status

The repository is currently private pre-release. This governance file is intentionally written for the planned public open-source phase so the process does not need to be invented at launch.
