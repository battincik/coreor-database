# Code of Conduct

Coreor Database aims to maintain a technical community where people can contribute, ask questions and review code without harassment, intimidation or unnecessary hostility.

This policy applies to project spaces including issues, pull requests, discussions, reviews and other official project communication channels.

## Expected behavior

Contributors and maintainers are expected to:

- discuss technical disagreements respectfully,
- criticize code and ideas rather than people,
- provide reproducible evidence when challenging behavior or implementation details,
- assume good intent while still addressing concrete security or quality problems directly,
- keep issue and pull-request discussions relevant to the project,
- respect privacy and avoid exposing another person's private information,
- avoid publishing credentials, private logs or sensitive infrastructure information,
- give credit for meaningful contributions,
- accept review feedback professionally,
- make space for contributors with different experience levels and backgrounds.

## Unacceptable behavior

The following are not acceptable in project spaces:

- harassment, threats or intimidation,
- discriminatory or demeaning language,
- personal attacks unrelated to technical work,
- repeated targeted disruption,
- sexual harassment or unwanted sexualized content,
- publishing another person's private information without permission,
- impersonation,
- deliberate disclosure of secrets or security-sensitive data,
- knowingly posting exploit details publicly while a vulnerability is under private coordination,
- spam, scams or malicious links,
- using project infrastructure to facilitate abuse of third-party systems.

## Technical disagreement

Strong disagreement is allowed. Personal hostility is not.

Good review language focuses on evidence:

- what fails,
- how to reproduce it,
- which security or compatibility assumption is incorrect,
- what alternative implementation is safer or simpler.

Maintainers may ask participants to stop repetitive or off-topic arguments after the technical decision and rationale have been documented.

## Security discussions

Security reports that could expose users, credentials, infrastructure or vulnerable deployments should follow [SECURITY.md](SECURITY.md).

Do not pressure reporters to publish exploit details before a fix and disclosure plan are ready.

## Enforcement

Maintainers may take actions including:

1. requesting a wording/behavior change,
2. hiding or removing abusive/off-topic content where platform controls allow,
3. locking a conversation,
4. limiting participation,
5. closing issues or pull requests used primarily for harassment/spam,
6. reporting serious abuse to GitHub or relevant platform administrators.

Enforcement should be proportionate to severity, repetition and impact.

## Maintainer responsibilities

Maintainers should:

- apply this policy consistently,
- avoid using moderation to silence legitimate technical/security criticism,
- separate conduct concerns from code-review outcomes,
- preserve security reports privately when required,
- explain moderation decisions when doing so does not create additional safety/privacy risk.

## Reporting conduct problems

For ordinary project moderation, report the relevant GitHub content through the platform and/or contact project maintainers through an appropriate private channel if available.

If the issue also involves a security vulnerability, use the private process described in [SECURITY.md](SECURITY.md).

## Scope

This code of conduct governs participation in Coreor Database project spaces. It does not attempt to regulate unrelated personal activity unless that activity directly threatens project participants or the safety of the project infrastructure.
